# VigilWatch architecture

## Components

| Component | Resource (Terraform) | Responsibility |
|---|---|---|
| Dashboard | `aws_s3_bucket.frontend`, `aws_cloudfront_distribution.frontend` | Static HTML/JS. `config.js` is generated by Terraform with the API URL |
| Public API | `aws_apigatewayv2_api.http` (HTTP API, `$default` stage) | Routes, CORS, throttling (5 rps, burst 10), access logs |
| `register_endpoint` Lambda | `aws_lambda_function.fn["register_endpoint"]` | Validate and register a URL, run its first check, return the dashboard payload |
| `get_checks` Lambda | `aws_lambda_function.fn["get_checks"]` | Return the dashboard payload for a URL (read-only role) |
| `uptime_check` Lambda | `aws_lambda_function.fn["uptime_check"]` | Probe all enabled URLs, persist results, drive incidents and alerts |
| Schedule | `aws_cloudwatch_event_rule.schedule` + target + permission | `rate(5 minutes)` |
| Storage | `aws_dynamodb_table.endpoints`, `aws_dynamodb_table.history` | Provisioned 5/5 each, TTL on `expires_at` |
| Alerts | `aws_sns_topic.alerts` (+ optional email subscription) | Endpoint DOWN/RECOVERED, alarm notifications |
| Dead letters | `aws_sqs_queue.checker_dlq` | Failed scheduled runs (no retries; the next run is minutes away) |
| Alarms | `aws_cloudwatch_metric_alarm.alarm[*]` | Health of the monitor itself |

## Code layout

```text
lambda/
  uptime_check.py        EventBridge handler: parallel probes, serial persistence, EMF metrics
  register_endpoint.py   POST /register
  get_checks.py          GET /checks?url=
  common/
    status.py            CheckResult, classify() -> UP / DEGRADED / DOWN
    urlguard.py          normalize(), validate() (SSRF guard), endpoint_id()
    checker.py           probe() (no redirects), apply_result() incident/alert state machine
    repo.py              DynamoDB access: endpoints, raw checks, rollups, incidents
    view.py              Dashboard payload shared by both API routes
    http.py              HTTP API v2 event parsing and JSON responses
```

All three functions ship in one zip built from `lambda/`. They use only the standard library
and the boto3 that the Lambda runtime provides.

## Data model

`endpoints` table, partition key `endpoint_id`:

| Attribute | Notes |
|---|---|
| `endpoint_id` | First 16 hex characters of sha256(normalized URL), so registering is idempotent |
| `url`, `method`, `expected_status`, `enabled`, `created_at` | Set on registration |
| `status`, `last_check`, `last_latency_ms`, `last_status_code`, `last_error` | Latest result |
| `consecutive_failures`, `open_incident_start`, `last_alert_sent` | Alert state machine |

`history` table, partition key `endpoint_id`, sort key `sk`:

| `sk` | Item | TTL |
|---|---|---|
| `C#<timestamp>` | Raw check: `status`, `status_code`, `latency_ms` | 48 hours |
| `D#<date>` | Daily rollup: `total`, `up` (atomic `ADD`) | 31 days |
| `I#<start timestamp>` | Incident: `resolved`, `end_time`, `duration_s` | 31 days |

The 30-day uptime is `sum(up) / sum(total)` over at most 30 rollup items, not a scan of ~8,600
raw checks. `DEGRADED` counts as up.

## Flows

**Register (POST /register `{"url": "...", "expected_status": 200}`)**
1. Parse the body (base64 aware); reject non-objects, bad `expected_status`.
2. `validate()`: http/https only, no credentials, length <= 2048, every resolved address public.
3. Upsert by `endpoint_id`; 429 if the cap (`MAX_ENDPOINTS`, default 10) is reached.
4. New URL: probe now and store the result, so the dashboard has data immediately. Returns 201.
   Existing URL: returns 200 with the current payload.

**Scheduled check (every 5 minutes)**
1. Scan enabled endpoints (at most 10).
2. Probe in parallel threads. Each probe re-runs the SSRF guard first (DNS can change).
3. For each result, serially: write the raw check and rollup, then update the state machine.
4. Print one EMF record (`ChecksRun`, `EndpointsDown`, `EndpointsDegraded`, `AvgLatencyMs`).
5. If any endpoint failed *internally* (e.g. a DynamoDB error), raise after processing the rest.
   That fails the invocation, which feeds the `checker-errors` alarm and the DLQ.

**Alert state machine (per endpoint)**

```text
            DOWN (failures < threshold)
   ┌──────────────┐
   v              │
 healthy ──DOWN──> failing ──DOWN (failures >= threshold)──> incident open
   ^                 │                                      (SNS "DOWN", once)
   │              UP │                                           │
   └─────────────────┘<──────────UP (SNS "RECOVERED", close)─────┘
```

The threshold is `FAILURE_THRESHOLD` (default 2), so one blip does not page anyone.

**Dashboard**
The page loads `config.js` for the API URL, registers the URL the user enters, renders the
payload, and polls `GET /checks` every 15 seconds. All server data is written with
`textContent`. The payload shape is pinned by
[tests/contract/checks_response.schema.json](../tests/contract/checks_response.schema.json),
which both the Python and the frontend tests load.

## Security design

- **Least privilege.** One IAM role per function, scoped to the specific tables, topic, queue
  and log group. `get_checks` is read-only. `terraform test` fails on any wildcard action or resource.
- **SSRF guard.** See [ADR 0004](adr/0004-zero-cost-security-tradeoffs.md). The functions run
  outside a VPC, so the only private target reachable is the Lambda runtime API on 127.0.0.1, and
  that is blocked.
- **HTTPS everywhere.** CloudFront redirects HTTP; API Gateway is HTTPS only.
- **Private bucket.** All public access blocked; CloudFront reads through Origin Access Control.
- **Headers.** CSP (`script-src 'self'`, `connect-src` limited to API Gateway in the region),
  HSTS, `X-Frame-Options: DENY`, `nosniff`, strict referrer policy.
- **CORS.** Owned by API Gateway and limited to the dashboard origin (plus localhost for development).
- **Abuse limits.** Stage throttling and the endpoint cap bound both load and cost.
- **CI/CD.** GitHub OIDC (no stored AWS keys), saved plans, manual approval, secret and IaC scanning.

## Observability

- **Logs.** Each function has its own log group (14-day retention). API access logs are JSON.
- **Metrics.** EMF from the checker, namespace `VigilWatch`, dimension `Service=uptime-check`.
- **Alarms** (all notify the SNS topic): `checker-errors`, `checker-not-running`
  (fewer than 1 invocation in 30 minutes, missing data counts as breaching), `checker-dlq`, `api-5xx`.
  The runbook explains each one.
